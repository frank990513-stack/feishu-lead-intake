# 字段与验收

## 飞书字段模板

`assets/feishu-fields.csv` 第一行为表头，后两行为虚构演示行。新建测试表可导入整份 CSV。手工配置时，将五个必填列和一个可选列都设为文本，避免原始编号被转成数字。

| 列名 | 规则 | 爱番番示例 | Gmail 示例 |
| --- | --- | --- | --- |
| 去重键 | 必填，稳定且完整匹配 | `baidu-aiff:demo-site:aiff-demo-001` | `gmail:demo-mailbox:gmail-demo-001` |
| 来源渠道 | 必填，供销售识别 | 百度爱番番·示例站 | 官网表单·示例 Google Ads 来源 |
| 原始编号 | 必填，保留来源编号 | `clueId` | Gmail API `id` |
| 询盘摘要 | 必填，简明且可追溯 | `additionalContent`，空时从有效会话提炼 | 留言提取值，可按明确字段加上产品 |
| 原始正文 | 必填，保留有效原文的纯文本 | 清洗后的 `formDetail`，保留对话顺序 | 已解码的邮件正文，保留字段与原始留言 |
| 联系邮箱 | 可选，缺失留空 | `emailAccount` | 表单的 `Email` 字段 |

去重键格式为 `来源类型:稳定来源标识:原始编号`，每段独立做 URL 百分号编码后再以冒号拼接。保留不透明 ID 的大小写。稳定来源标识是已配置的站点或邮箱别名，面向人的渠道展示名可以调整。一个邮箱收多个站点的通知时，Gmail 消息的去重键仍用邮箱别名。同一个客户跨平台发来两条不同询盘时，各自保留，客户合并属于 CRM 的后续动作。

## 验收用例

| 用例 | 怎么做 | 预期 |
| --- | --- | --- |
| 正常入表 | 爱番番样例 `normal` 和 Gmail 样例 `normal` 各送一次 | 各新增一行，来源正确，摘要与正文分别保存，结果与 CSV 一致 |
| 重复投递 | 分别再次送入两条 `normal` | 两次均跳过，去重键各只有一条，原行保留 |
| 占位符 | 送入爱番番样例 `unresolved_placeholder` | 记为 `unresolved-placeholder`，待查且零新增 |
| 空留言 | 送入 Gmail 样例 `empty_inquiry` | 记为 `empty-inquiry`，待查且零新增 |
| 单行通知 | 送入 Gmail 样例 `flat_body` | 提取到「希望了解 2 台的交付周期。」并新增一条，邮箱和原文齐全 |

如已从模板 CSV 导入两条正常演示行，先回查它们，再用一张仅保留表头的新测试表运行正常与重送用例。排查时保留两个对照值：收到的有效原文和最终写入字段。有正文但留言为空时，核对解码、字段标签和备用解析。若原文也没有提供可用信息，仍标待查，等来源侧确认。

离线脚本覆盖上表，写入和去重发生在内存。真实接入验收需额外比对来源端的独立提交、接收记录和飞书回查。同键在真实表上的可重复投递、并发和超时恢复取决于部署，需要在测试环境验收后再启用生产写入。
